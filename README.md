# INDICATE WLC Dashboard

> **Work in progress.** These results are preliminary and haven't been verified yet. Data harmonisation and assumptions are still being checked with the INDICATE LIFE national teams. Please don't cite or reuse the figures.

A web dashboard showing the whole life carbon (WLC) of buildings across the INDICATE LIFE national datasets:

| Deliverable | Country | Buildings | Lead organisation |
|---|---|---|---|
| D7.3 AT national WLC dataset | Austria | 67 | TU Graz |
| D7.12 HR national WLC dataset | Croatia | 50 | University of Zagreb, Faculty of Civil Engineering |
| D7.21 IT national WLC dataset | Italy | 50 (29 new, 21 renovations) | POLIMI, with POLITO, UNIBG and Harpaceas |
| D7.30 LU national WLC dataset | Luxembourg | 52 | Energie et Environnement S.A. (on behalf of the OAI) |

It shows the distribution of WLC per m² by building type, contributions across life-cycle modules (A1–A3 … C1–C4, D), contributions by building element (Italy and Luxembourg, each in its own classification) and material (Luxembourg), statistical benchmark classes (Target ≤ P25, Reference ≤ P50, Limit ≤ P75, Above limit) and the building-level records. A *Method and data notes* section on the page documents the harmonisation choices and open assumptions.

INDICATE LIFE, National Building LCA Data Accelerator EU LIFE, is co-funded by the European Union's LIFE programme under grant agreement 101167585. Website: <https://www.indicatedata.com/>

## Repository contents

```
index.html                          the dashboard (static HTML, CSS and JavaScript, no build step)
assets/js/data.js                   dashboard data, generated by the pipeline
assets/css/fonts.css, assets/fonts/ self-hosted web fonts (SIL Open Font License 1.1)
data/INDICATE_WLC_database.xlsx     harmonised database: buildings, results, statistics, elements,
                                    mappings, issues log, QA checks, processing steps
data/csv/                           the main database tables as CSV
pipeline/                           Python harmonisation pipeline; see pipeline/README.md
robots.txt                          keeps search engines away while this is a preview
.nojekyll                           tells GitHub Pages to serve the files as they are
```

The page runs entirely in the browser. It has no server, database, cookies, analytics or browser storage, and loads nothing from third-party servers (the fonts are included in the repository).

## Publish with GitHub Pages

1. Create a new repository on GitHub, e.g. `indicate-wlc-dashboard`. Public repositories can use Pages on every GitHub plan.
2. Upload the **contents** of this folder to the root of the repository. On the web: *Add file → Upload files*, drag in everything including the `assets`, `data` and `pipeline` folders, then commit. `.nojekyll` is a hidden file; if it doesn't upload, the site still works without it.
3. Go to *Settings → Pages → Build and deployment*: choose **Source: Deploy from a branch**, **Branch: `main` / `(root)`**, then *Save*.
4. After a minute or two the dashboard is live at `https://<account>.github.io/indicate-wlc-dashboard/`.

To test locally, open `index.html` directly in a browser, or run `python -m http.server` in this folder and visit <http://localhost:8000>.

### Custom domain later (e.g. `dashboard.indicatedata.com`)

To be agreed with the partners. When ready:

1. In the DNS settings for `indicatedata.com`, add a **CNAME** record: host `dashboard`, value `<account>.github.io`.
2. In the repository, go to *Settings → Pages → Custom domain*, enter `dashboard.indicatedata.com`, save, and tick **Enforce HTTPS** once the certificate is issued.

## Updating the data

The source workbooks aren't stored in this repository. To rebuild the database and the dashboard data after a dataset update or a new country:

```bash
pip install -r pipeline/requirements.txt
python pipeline/run_all.py path/to/source-folder   # folder holding the four .xlsx deliverables
```

This rewrites `data/` and `assets/js/data.js`. Commit them and Pages republishes automatically. The run prints the processing log and the reconciliation checks, and stops if a check fails. See `pipeline/README.md` for the processing steps.
