Method and data notes

Harmonisation

  • The database follows the INDICATE reporting template v1.1: attribute codes, the 16 template modules (A1–A3 … D2) and the 9 template building types. Values reported only as a sum of modules (B4–B5, C1–C4, C3–C4, D) are kept as such and flagged.
  • Values are GWP-total in kgCO₂e over a 50-year reference study period; “per year” divides by 50. Charts group the modules into A1–A3, A4, A5, B1–B3, B4–B5, B6, B7, C1–C4 and D.
  • Embodied = A1–A3, A4, A5, B1–B3, B4–B5 and C1–C4, as reported by each dataset (B1–B3 only by Croatia and Italy), the same definition as the D3.2 synthesis report. Whole life adds B6 and B7 where reported. Module D is always shown separately.
  • Floor areas. GFA as reported. NFA is the template's net floor area: usable floor area (UFA) for Austria, Croatia and Luxembourg, heated floor area (HFA) for Italy.
  • Intervention. Italy includes 21 renovations (13 minor, 8 major). They are shown only when the intervention filter includes renovation, and are benchmarked separately from new construction. Austria and Luxembourg do not state the intervention type and are treated as new construction.
  • Building types follow the template list (SFH, MFH, ABL, OFF, TRA, EDU, HEA, HOR, OTH). Multi-family houses map to MFH and apartment buildings to ABL (Austrian “Apartment block”, Luxembourg “Apartments”). National typologies are kept in the building table.

Assumptions to confirm

  • Luxembourg reference area. The LU results are already per m², but the file does not state which area. They are treated as per m² UFA, because the D3.2 synthesis report (Table E.1, per m² UFA) gives exactly the same module statistics. Values per m² GFA are converted with the A. Metadata areas.
  • Italy, floor area. Italy reports GFA and heated floor area (HFA) but no UFA; HFA is used as NFA.
  • Italy, typologies HOS and XTR. Not defined in the file. HOS is mapped to HOR (hospitality), following D3.2, which describes these cases as mainly long-term stays and student rooms (D3.2 groups them with MFH for its benchmarks). XTR is mapped to OTH. Both to be confirmed by the Italian team.
  • Element mapping. Neither the Luxembourg LEVELS codes nor the Italian tiers are named in the files. Both are mapped to the EU Delegated Regulation Table 4 tiers from their content (Italian tiers 2.2–2.9 read as the EU building-services list); to be confirmed. Italy, element tiers: Tier values include proxies for missing values, outlier replacements and cross-typology proxies, flagged by cell colour in the source; tier sums are 0.92–1.69× the life-cycle embodied totals (median 1.07).
  • Austria, operational energy. The column header reads “GWP total - B5” but its description row says B6; it is treated as B6, which D3.2 confirms. Austrian B4–B5 contains B4 only.
  • Luxembourg “House” includes some larger multi-unit residences (e.g. MI_Con_1, 35 occupants); it is mapped to SFH as labelled.

Data quality flags

  • Croatia: the 50 cases are design variants of 16 base buildings (pairs share identical floor areas), so percentiles describe variants rather than an independent stock. The per-GFA B3 column in the source holds a running index; values here are recomputed from the absolute totals (which match the source totals within 2 kgCO₂e).
  • Austria reports no GFA, so it drops out when the area is set to GFA.
  • Luxembourg: the export file has no operational modules (B6/B7), so Luxembourg drops out of the whole-life view (D3.2 reports LU operational values from the national report; requested); its element scope covers shell, core and services plus external works.
  • Italy: B2, B3 and C1 are GWP-fossil only (used as GWP-total); B6 = 0 for IT-EDU_01 and IT-XTR_07 is treated as not reported; IT-OFF_07 and IT-OFF_08 report an identical B6 value, as do the four variants IT-MFH_17/20/21/25.
  • System boundaries and element scope of the AT and HR models are not documented in the files, so cross-country gaps may reflect scope as well as performance.
